Репозиторий с лабораторными работами по дисциплине «Теория алгоритмов».

## Лабораторная работа № 1. Введение в язык программирования Python

Одиннадцать заданий на базовые конструкции языка: числа, срезы строк, списки,
кортежи, множества, словари и вложенные структуры данных. Логика заданий
вынесена в функции, собрана под верхнеуровневым модулем `main.py` и покрыта

## Инкапсуляция логики

Изначально код заданий выполнялся прямо на уровне модуля, поэтому при импорте
файл сразу печатал результат в консоль. Чтобы модули можно было переиспользовать,
структура каждого файла приведена к единому виду:

- исходные данные остаются на уровне модуля;
- вычисления вынесены в функции, которые принимают данные параметром и
  возвращают результат через `return`;
- вывод на консоль собран в функции `run()`;
- в конце файла стоит проверка `if __name__ == '__main__': run()`.

Благодаря последней конструкции файл работает и как самостоятельный скрипт, и как
импортируемый модуль: при прямом запуске `__name__` равно `'__main__'` и `run()`
вызывается, при импорте — нет.

Разделение вычислений и печати понадобилось и для тестирования: проверить можно
только то, что функция возвращает, а `print()` ничего не возвращает.

## Верхнеуровневый модуль

Имена файлов заданий начинаются с цифры, а имена модулей в Python подчиняются
правилам имён переменных, поэтому обычный импорт невозможен:

```python
import python_lab_01.00_distance    # SyntaxError
```

Модули импортируются по строковому имени через `importlib`:

```python
from importlib import import_module

module = import_module(f'python_lab_01.{task}')
module.run()
```

`main.py` хранит список имён модулей, в цикле импортирует каждый и вызывает его
функцию `run()`.

## Установка

```bash
git clone https://github.com/urifar/Alg_theory.git
cd Alg_theory
```

Создание и активация виртуального окружения:

```bash
python -m venv .venv
source .venv/Scripts/activate      # Git Bash в Windows
source .venv/bin/activate          # Linux и macOS
```

Установка зависимостей:

```bash
python -m pip install -r requirements.txt
```

## Запуск

Все задания подряд:

```bash
python main.py
```

Отдельное задание:

```bash
python -m python_lab_01.00_distance
```

## Тестирование

Тесты находятся в `tests/test_lab.py` и проверяют функции модулей, а не вывод на
консоль. Запуск из корня проекта:

```bash
python -m pytest -v
```

Результат: 28 тестов, все проходят.

`pytest` находит тесты по соглашению об именах: файлы `test_*.py` и функции,
имена которых начинаются с `test_`. Запуск именно через `python -m pytest`
добавляет корень проекта в пути поиска модулей, иначе пакет `python_lab_01` не
будет найден.

## Шпаргалка по командам Git

| Команда | Назначение |
|---|---|
| `git clone <url>` | клонировать удалённый репозиторий |
| `git status` | состояние рабочей директории и индекса |
| `git branch` | список локальных веток, активная помечена `*` |
| `git switch -c <ветка>` | создать ветку и переключиться на неё |
| `git switch <ветка>` | переключиться на существующую ветку |
| `git add <файл>` | добавить файл в индекс |
| `git add .` | добавить все изменения в индекс |
| `git commit -m "сообщение"` | зафиксировать изменения локально |
| `git push` | отправить коммиты в удалённую ветку |
| `git push -u origin <ветка>` | первая отправка новой ветки с привязкой upstream |
| `git pull` | получить и влить изменения из удалённой ветки |
| `git log --oneline` | история коммитов в компактном виде |
| `git diff` | изменения, ещё не добавленные в индекс |

окружение `.venv/`, кеши `__pycache__/`, `.pytest_cache/`, `.mypy_cache/` и
настройки среды разработки.
